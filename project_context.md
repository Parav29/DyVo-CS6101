# Project context: DyVo reproduction (CS6101)

_Written 2026-09-29. Snapshot of what we are doing, on what hardware, and where everything lives. Live numbers: `repro_codec/REPORT.md` (regenerated by `scripts/big_pc/codec_report.py`) and `results/results.csv`._

## 1. What the project is
Course project (CS6101): reproduce **DyVo** ("Dynamic Vocabularies for Learned Sparse Retrieval with Entities", paper PDF: `cs6101_DyVo.pdf`). DyVo extends a learned sparse retriever (LSR-w, a DistilBERT-MLM encoder over the 30,522 word-piece vocabulary) with **entity** dimensions: for each query/document a candidate set of Wikipedia entities is scored and added to the sparse vector, so retrieval matches on words *and* entities.

- Upstream code: `DyVo/` (authors' repo, with our fixes). Everything we added is marked `DYVO-REPRO`.
- Scope of the reproduction: **CODEC only** (Table 1 rows at L1 = 1e-5, Table 2 candidate sources). Robust04 and TREC Core 2018 are skipped because they need NIST licences; no unofficial copies used. No proposed extensions are implemented.
- Goal: our numbers next to the paper's, e.g. CODEC nDCG@10: LSR-w 52.61, DyVo (REL) 53.40, DyVo (GPT-4 candidates) 56.46, DyVo (Mixtral) 54.90.

## 2. Compute
Shared university GPU server (other users' jobs run on the same GPUs; this is why speeds fluctuate and why OOMs happen).

| Resource | Details |
|---|---|
| GPUs | 2 × NVIDIA RTX A5000, 24 GB each (paper used 1 × A100) |
| CPU | AMD Threadripper PRO 5975WX, 32 cores / 64 threads |
| RAM | 125 GB total; a DyVo process needs ~38 GB (16 GB LaQue entity table loaded into CPU RAM), so **only one DyVo process fits at a time per ~45 GB free** |
| Disk | NFS home, 3.4 TB free. `DyVo/dyvo_data` 17 GB, `scratch` 15 GB, `DyVo/outputs` 15 GB |
| Software | `.venv-gpu` (uv Python 3.10), torch 2.2.2+cu121, transformers 4.40.2, fp16 |
| Tracking | `WANDB_MODE=offline` |

**Settings differing from the paper (deviations, all recorded in `repro_codec/REPORT.md`):**
- Batch = **4 per device × 4 gradient accumulation = 16** (paper batch 16) so it fits in 24 GB with other jobs alongside.
- Extra **20k-step "course budget"** runs (10 % warm-up + linear decay scaled to 20k) next to the paper-length **100k-step** runs.
- Eval batch 8 (instead of 64) for the repair-lane jobs so they fit next to the two 100k runs; scores don't depend on it.

## 3. Data
Downloaded from the authors' HF dataset (`lsr42/dyvo_data`) into `DyVo/dyvo_data/`; CODEC corpus (729,824 docs) from public HF mirror into `~/.ir_datasets/codec`.

- Training queries: 5.6k CODEC queries with REL entities + Mixtral synthetic queries; teacher = MonoT5-3B scores (`codec_monot5_3b_scores.json`).
- Test: 42 CODEC topics, full-corpus retrieval, top 10,000.
- Entity candidates at test time: REL (default), GPT-4, Mixtral, BM25, LaQue, human. All ship in the authors' data repo. **No paid API key or local LLM is needed**. Training always uses REL entities; only test-time query candidates differ between REL/GPT-4/Mixtral rows.
- Entity embeddings: LaQue (16.2 GB table).
- Init checkpoint: authors' MS MARCO-pretrained `dyvo_init`.

## 7. Bugs found and fixed while running
- **Stale scratch dir crash** (`lsr/trainer/__init__.py`, `evaluation_loop_iterative_vectorized`): cleanup of `queries.jsonl` and `docs/` shared one `try`, so a missing queries file skipped `rmtree(docs)`, then `docs_dir.mkdir()` raised `FileExistsError`. Fixed: independent cleanup, `mkdir(exist_ok=True)`. The two 100k DyVo/LSR-w processes loaded the old code before the fix, so DyVo 100k will hit it unless its scratch dir is clean at test time; the phase-2 evals are re-runnable from saved models.
- Earlier build-phase fixes (missing loss imports, Wiki2Vec `entity_dim`, etc.): `SANITY_REPORT.md`, `ERRORS.md`, `NOTES.md`.
- Harmless: `faiss.swigfaiss_avx2` import warning (falls back to generic build).

## 8. Health checks to apply to any DyVo log
1. `query #entities` and `doc #entities` stay > 0 (0 = entity collapse).
2. `loss_no_reg` finite (NaN = negative teacher scores).
3. Result within ~1–2 nDCG@10 points of the paper (10+ = miswired).
