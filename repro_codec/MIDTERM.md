# DyVo reproduction: midterm assessment and plan

Paper: *DyVo: Dynamic Vocabularies for Learned Sparse Retrieval with Entities* (`cs6101_DyVo.pdf`).
Code: official repository `thongnt99/DyVo` (in `DyVo/`), extended only where needed (every edit is marked `# DYVO-REPRO`).
Live results: `repro_codec/REPORT.md` (regenerated by `python scripts/big_pc/codec_report.py`).

## Status assessment

**1. Headline experiment.** DyVo adds Wikipedia entities to a learned sparse retriever (LSR). A DyVo head scores a small set of candidate entities against the encoder's hidden states, and those entity weights are appended to the word-piece weights. Three claims form the headline:
- DyVo beats the word-only LSR baseline (LSR-w) when both use linked (REL) entities (Table 1).
- The paper's new few-shot generative candidate retrieval (Mixtral / GPT-4) gives the largest gains (Table 2).
- Both hold across three entity-rich datasets.

**2. Main reproduction target.** Table 1 (L1 = 1e-5 rows) and Table 2, CODEC columns. Robust04 and TREC Core 2018 need NIST licences, so they are out of scope (see Phase 7).

**3. Target numbers (CODEC).**

| Row (paper) | nDCG@10 | nDCG@20 | R@1k |
|---|---:|---:|---:|
| LSR-w, L1 = 1e-5 (Table 1) | 52.61 | 49.22 | 69.07 |
| DyVo (REL) (Tables 1, 2) | 53.40 | 51.15 | 70.60 |
| DyVo (Mixtral) (Table 2) | 54.90 | 52.82 | 73.20 |
| **DyVo (GPT4) (Table 2, best CODEC row with LaQue)** | **56.46** | **53.72** | **74.47** |

**4. Dataset.**
- **Test data:** CODEC (42 topics, 729,824 documents, graded qrels) via `ir_datasets` (`irds:codec`).
- **Training data:** the authors' 10k Mixtral-generated CODEC queries, with MonoT5-3B teacher scores (`dyvo_data/codec/`).

**5. Models and checkpoints.** All come from the authors' HF dataset `lsr42/dyvo_data`:
- **Init checkpoint:** DistilBERT query/doc encoders pre-trained on MS MARCO (`dyvo_init/`).
- **Entity embeddings:** LaQue, 5.28M × 768 (`knowledge_base/entity_embs_laque.pt`).
- **Entities:** REL-linked entities for queries and documents, plus the authors' GPT-4 / Mixtral query-entity outputs.

No trained CODEC checkpoints were released, so we train our own.

**6. What already existed.**
- **Code:** the official code covers model, entity head, collator, loss, trainer, evaluation (ir_measures) and all experiment configs.
- **Earlier work (build machine):** six upstream bug fixes, 61 unit tests, smoke runs, and the big-PC scripts.

**7. What was missing, and what was added.**
- Six upstream bugs that stopped any run (see `SANITY_REPORT.md`).
- The configs only wire REL entities; the LLM rows were added through `merge_candidates.py` plus inference configs.
- Budget configs for a shared 24 GB GPU.
- The reproduction record in `repro_codec/`.

**8. Downloads and configuration.**
- `lsr42/dyvo_data` (CODEC + LaQue: about 17 GB).
- The CODEC corpus from its public Hugging Face copy (`macavaney/codec`), placed at `~/.ir_datasets/codec/v1/comets_documents.jsonl`.
- A Python 3.10 environment with torch 2.2.2+cu121.

## Phase 3 — Model (done)
- **Official configs:** `qmlp_dmlm_codec_…_l1_0.0_0.00001` (LSR-w) and `qmlp_dmlm_emlm_laque_codec_…_entw_0.05` (DyVo) are used unchanged.
- **Encoders:** MLP query encoder and MLM document encoder, DistilBERT, both from `dyvo_init`.
- **DyVo head:** λ_ent initialized to 0.05 (trainable), LaQue entity embeddings.
- **Checks:** a trial of 40 DyVo steps showed a finite loss and entities active (about 0.9 per query, 20 per document), so no collapse.

## Phase 4 — Reproduction (running)
Every run keeps the paper's settings (learning rate 5e-7, 10% warm-up, KL distillation from MonoT5-3B, L1 = 1e-5 on documents, 512-token documents, fp16, seed 42) with an **effective batch of 16**, built as batch 4 × 4 gradient accumulation so it fits in 6 GB of GPU memory.

| Run | Steps | Purpose |
|---|---|---|
| `*_full100k` (LSR-w, DyVo) | 100k (paper) | **the reproduction** |
| `*_full100k_eval_{gpt4,mistral}` | inference only | Table 2 rows: the trained DyVo model with LLM query candidates at test time, as the paper does |
| `*_course20k` (+ evals) | 20k | fallback result if the 100k runs are not done by the deadline |
| `*_init` | 0 | the MS MARCO init with no CODEC training (how much training adds) |

Orchestration: `scripts/big_pc/run_codec_course.sh` (20k + init) and `scripts/big_pc/run_codec_phase2.sh` (100k + LLM evals). Both run under `nohup` and skip finished runs.

## Phase 5 — Evaluation (automatic)
- **Procedure:** the official `trainer.predict` encodes all 729,824 documents and scores them exhaustively against the 42 test queries (top-10k kept). ir_measures then computes nDCG@10, nDCG@20 and R@1000, exactly the paper's metrics.
- **Output:** `DyVo/outputs/<exp>/<date>/{test_run.trec,test_result.json}`.

## Phase 7 — Discrepancy analysis (known sources; to be weighed against the numbers)
1. **Datasets:** CODEC only. Robust04 and Core 2018 need NIST licences, and no unofficial copies were used.
2. **Hardware:** RTX A5000 24 GB on a shared machine vs. A100. Only speed differs, but it forced gradient accumulation, which leaves the objective the same: KL and L1 are batch means, and each query is scored only against its own positive/negative pair.
3. **Random seed / single run:** one run per row, as in the paper. CODEC has only 42 test queries, so differences of about 1 point are within noise.
4. **Numerical non-determinism:** fp16 and GPU kernels can make re-runs differ slightly.
5. **Library versions:** the paper states none. We use torch 2.2.2, transformers 4.40.2 and ir_measures 0.4.3; wandb is pinned to 0.16.6 because newer versions break the code.
6. **Implementation details that differ between paper and code (the code is kept):**
   - λ_ent sits inside the ReLU (Eq. 4 puts it outside).
   - `normalize: "std"` is actually L2 normalization.
   - The DyVo collator truncates queries at 512 tokens, while LSR-w truncates at 50.
7. **Upstream bug fixes:** six fixes that don't change the model math (missing imports, a missing attribute, a missing fold config, the Wiki2Vec dimension, a hard-coded scratch path, the wandb API).
8. **Candidate reuse:** the GPT4/Mixtral rows evaluate the REL-trained model with LLM candidates, following the paper's statement that GPT-4 candidates are used "on queries for inference". The paper may have trained a separate model per row; with the same data and seed, the two should be equivalent up to non-determinism.
9. **Corpus source:** the public Hugging Face copy of CODEC linked by the CODEC authors. It holds the same 729,824 documents; ir_datasets still says "on request".
10. **Fallback only:** the 20k-step rows are shorter training by design, and their numbers are expected to be lower.
